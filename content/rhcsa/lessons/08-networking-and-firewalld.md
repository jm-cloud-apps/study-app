# Networking with nmcli, and firewalld

> **The one-sentence version:** On RHEL, network configuration means editing a **NetworkManager connection profile** with `nmcli` — not `ip addr`, which evaporates — and the firewall means adding a service or port to a **firewalld zone** with `--permanent`, then reloading.

Both tools follow the same shape as the rest of the exam: there's a runtime change and a persistent one, and only the persistent one counts.

## Why it matters

A static IP, a hostname, and an opened port are the supporting cast of half the tasks on the exam (you can't verify a web server task if the port is closed). And both tools have the same trap: the obvious command changes the running system only.

> 💡 If subnets, routing, or what `ss` is actually showing you feel shaky, the **Networking Fundamentals** topic covers the layer underneath this one — CIDR, routing and NAT, TCP/UDP and ports, and the troubleshooting toolkit. This lesson assumes those and concentrates on the RHEL tooling.

## The mental model

🔑 **NetworkManager owns the network.** A **device** is the hardware (`enp1s0`). A **connection profile** is a named bundle of settings that can be applied to a device. You edit profiles; NetworkManager applies them, and re-applies them at boot. Anything you do with `ip addr add` behind NetworkManager's back is gone at the next reboot or the next time the profile is brought up.

```bash
nmcli device status            # devices, their state, and which profile is active
nmcli connection show          # all profiles
nmcli connection show static0  # every setting in one profile
ip addr ; ip route             # read-only reality check
```

Profiles are stored as keyfiles under `/etc/NetworkManager/system-connections/`. Reading one is a good way to confirm what you configured.

## Setting a static address

Create a new profile:

```bash
nmcli connection add type ethernet con-name static0 ifname enp1s0 \
  ipv4.method manual \
  ipv4.addresses 192.168.1.10/24 \
  ipv4.gateway 192.168.1.1 \
  ipv4.dns "192.168.1.53 192.168.1.54" \
  autoconnect yes
```

Or modify an existing one:

```bash
nmcli connection modify static0 ipv4.addresses 192.168.1.20/24
nmcli connection modify static0 +ipv4.dns 8.8.8.8      # ADD a DNS server
nmcli connection modify static0 -ipv4.dns 8.8.8.8      # remove one
nmcli connection modify static0 ipv4.method auto       # back to DHCP
```

> ⚠️ **Changes don't take effect until the profile is reactivated.** `nmcli connection up static0` (or `nmcli device reapply enp1s0`). This catches people constantly: the config is right, `ip addr` disagrees, and everything looks broken. Bring the connection up.

The `+`/`-` prefixes are worth remembering: plain `ipv4.dns` **replaces** the list, `+ipv4.dns` appends to it. Same mistake shape as `usermod -aG`.

## Hostname and name resolution

```bash
hostnamectl                              # current hostname and system info
hostnamectl set-hostname web1.example.com
```

Static entries go in `/etc/hosts` — often exactly what a task wants when there's no DNS server:

```
192.168.1.10   web1.example.com   web1
```

`/etc/resolv.conf` is generated by NetworkManager, so set DNS with `nmcli … ipv4.dns` rather than editing that file. Test with `host`, `dig`, or `getent hosts web1` (the last one follows the same resolution order the system actually uses).

## Useful checks

```bash
ping -c3 192.168.1.1
ss -tulpn                   # listening sockets: -t tcp -u udp -l listening -p process -n numeric
ss -tulpn | grep :80
ip -br addr                 # a compact summary
```

## firewalld

firewalld sorts traffic into **zones**. Each interface belongs to one zone, and the zone's rules decide what's allowed. On a typical server everything is in `public` and you never touch zones again — but knowing they exist explains the `--zone=` flag everywhere.

```bash
firewall-cmd --state
firewall-cmd --get-default-zone
firewall-cmd --get-active-zones
firewall-cmd --list-all                 # everything about the default zone
firewall-cmd --list-all --zone=public
```

### Allowing things

```bash
firewall-cmd --permanent --add-service=http
firewall-cmd --permanent --add-service=https
firewall-cmd --permanent --add-port=8080/tcp
firewall-cmd --reload                   # apply the permanent config NOW
firewall-cmd --list-all                 # verify
```

> 🔑 **`--permanent` writes the config but doesn't apply it; without it you change the runtime but lose it at reboot.** Two safe habits: run the command with `--permanent` and then `--reload`, or configure at runtime, test, and freeze it with `firewall-cmd --runtime-to-permanent`. Either is fine — silently doing neither is what fails.

`firewall-cmd --get-services` lists the predefined service names; prefer `--add-service=http` over `--add-port=80/tcp` when a named service exists, because it's what the task usually means and it covers all the ports that service needs.

### Sources, interfaces, and rich rules

```bash
firewall-cmd --permanent --zone=trusted --add-source=192.168.5.0/24
firewall-cmd --permanent --zone=internal --change-interface=enp7s0
firewall-cmd --permanent --add-rich-rule='rule family=ipv4 source address=192.168.5.10/32 service name=ssh reject'
firewall-cmd --permanent --add-forward-port=port=8080:proto=tcp:toport=80
firewall-cmd --permanent --add-masquerade
firewall-cmd --reload
```

Rich rules are how you express "this source, this service, this action" when a plain service rule is too blunt. Read them left to right — family, source, service, action.

> 💡 If a service is running and locally reachable but not from another host, the order to check is: is the daemon **listening** on the right address (`ss -tulpn` — `127.0.0.1` only is a common trap), is the **firewall** allowing it (`firewall-cmd --list-all`), and is **SELinux** blocking a non-standard port (next lesson).

## Key takeaways

- **NetworkManager owns the config**: edit profiles with `nmcli connection add/modify`, then **`nmcli connection up`** to apply. `ip addr` is for reading, not configuring.
- `+`/`-` prefixes append and remove list values; plain assignment replaces the whole list.
- `hostnamectl set-hostname` for the name, `/etc/hosts` for static resolution, `nmcli … ipv4.dns` instead of editing `/etc/resolv.conf`.
- firewalld works in **zones**; `--permanent` + `--reload` is the persistent pattern, and `--runtime-to-permanent` saves what's already live.
- Prefer `--add-service=` over raw ports, and debug "can't reach it" as **listening → firewall → SELinux**.
